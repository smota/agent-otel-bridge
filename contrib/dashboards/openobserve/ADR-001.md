# ADR-001: Collector edge integration and dashboard ownership

Date: 2026-11-05. Status: accepted for this package.

OpenObserve is a telemetry backend, not an AI harness. Route existing OTLP traces
and metrics at the Collector edge using the illustrative Collector Contrib
exporters. Preserve existing pipelines when integrating. No harness registry,
provider descriptor, daemon, IPC, hook or client changes are needed or included.

Own the five dashboard identities through one exact leading description marker,
`agent-otel-bridge:openobserve:<key>`, with server-assigned dashboard IDs resolved
after creation. Reject ambiguous markers, unmanaged title collisions and
unsupported versions. Back up updates outside the repository and bind rollback
receipts to the PUT result's hash and canonical definition digest, verified by
GET. Rollback cannot erase subsequent edits and never deletes created dashboards.

The target is OpenObserve OSS v1.1.2. Personas and variable filters organize views;
they provide no data isolation or RBAC. Permission automation remains absent and
`--require-rbac` fails closed pending independent edition-specific validation.

Dashboard writes can register distinct values and update stream settings before
dashboard persistence. Dashboard backups/rollback do not restore those settings;
operators must capture and recover them separately as described in [README.md](README.md).
The Collector example and generated artifacts do not establish live deployment
or UI acceptance.
