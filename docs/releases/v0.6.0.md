# Release v0.6.0 — Harness Integration and Repeatable Performance Diagnostics

This minor release improves local harness integration and adds tools for investigating telemetry delivery across the production pipeline.

## Harness integration

- PreToolUse responses for supported clients forward inherited TRACEPARENT in hook environment output. Unsafe characters are omitted to keep the JSON response valid; Codex retains its empty response contract. End-to-end adoption depends on the harness consuming this output.
- Pi uses a managed native extension for tool, session and agent events. Installation preserves extensions it does not own.
- Windows hook generation handles Antigravity shell quoting and avoids duplicate Grok telemetry from imported Claude hooks.
- Event parsing accepts camelCase and snake_case payload fields. Doctor provides more detailed hook and runtime diagnostics.

## Production pipeline and diagnostics

- Windows IPC uses a bounded pool of pending listeners, with regression coverage for concurrent delivery, duplicate ownership and shutdown.
- Production transformation is shared with the benchmark path. Parser throughput, transformation, context lookup and direct harvesting are measured separately.
- Hook timing records response and transport stages so internal execution can be distinguished from process startup and shell overhead.

## Repeatable benchmark laboratory

The source-only laboratory adds seeded profiles, configuration and report schemas, a ClickHouse reader, offline verification tests and structured reports. It remains excluded from published runtime packages.

Reports also render when candidate binary hashes are unavailable. Laboratory tests isolate subprocess mocks from Windows platform detection.

## Upgrade

Download the Windows archive and its SHA-256 checksum from this release. Extract it and use the included CLI to activate both binaries together:

```powershell
.\agent-otel-bridge.exe local install --from-build .
```

The installer stages the binaries and preserves rollback state. Run `agent-otel-bridge doctor` after installation.

## Validation limits

IPC admission loss under sustained stress remains open in [RES-004](https://github.com/smota/agent-otel-bridge/blob/v0.6.0/docs/resilience-backlog.md). This release does not claim loss-free delivery for every workload or certify native Linux/macOS performance. Live harness and backend acceptance must be established separately from source tests.
